# 启动、菜单、设置与加载

| 功能 ID | 源项目行为合同 | GF 目标重构方式 | 验收 |
|---|---|---|---|
| CT-FLOW-01 | `Launch` 为唯一入口，最终进入 StartMenu；不直接运行 Boss 场景。 | StartupProcedure 编排启动和场景请求。 | 从 Launch 启动，检查服务与首场景。 |
| CT-FLOW-02 | 菜单开场视频播放一次，结束后切换循环视频。 | MainMenu GF UIForm 持有视频播放控制与回调。 | 录制开场至循环切换。 |
| CT-UI-01 | 开始／关卡选择／设置可互相打开和返回；无重叠页面或残留遮罩。 | 页面为独立 GF UIForm 或明确的页面状态，遵守 GF UI 标准。 | 逐按钮往返并检查层级。 |
| CT-FLOW-03 | 开始进入 Boss1；关卡选择可进入 Boss1 或 Boss2；退出仅在 Player 验证。 | 统一通过项目 SceneFlow 与项目 Loading Form。 | 每条路径检查一次 Loading 和目标场景。 |
| CT-SET-01 | BGM、SFX、Key Tip 开关互斥且跨菜单／暂停保持。 | 设置数据由项目配置／持久化接口统一读写；声音经 GF.Sound。 | 切换、离页、暂停、返回菜单后复验。 |
| CT-FLOW-04 | Escape 暂停、继续、重开、跳关、返回菜单；暂停时 UI 可点，恢复后时间正常。 | Pause UIForm 控制时间尺度和输入封锁；场景请求仍走 SceneFlow。 | 覆盖每个按钮及死亡后的重开。 |
| CT-LOAD-01 | 每次切换有淡入淡出和单调进度，无重复、黑屏卡死。 | 项目 Loading Form 负责输入封锁、进度和 unscaled fade；框架 BuiltinView 默认进度暂不显示但保留错误对话框。 | 转换三条场景路径，观察单实例和关闭时机。 |

## 所有权约束

- `StartMenu` 不再静态保存 `LoadScene_s`，也不保存菜单 BGM `AudioSource`。
- `Loading.prefab` 是项目通用 GF.UI Prefab，不是场景对象；必须在 UI 表／资源集合中注册。
- 若将来需要启动动画，再明确启用或替换 Launch 的 BuiltinView；当前进度条本身不是启动体验需求。
