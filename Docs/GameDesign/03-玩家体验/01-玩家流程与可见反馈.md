# 玩家流程与可见反馈

## 主流程

```text
Launch
→ StartMenu 开场视频 / 循环视频 / BGM
→ 开始或关卡选择
→ Loading（封锁输入、进度、淡出）
→ Boss1：观察颜色弱点 → 拾取对应武器 → 攻击、躲避、Dash
→ Boss1 胜利 Loading
→ Boss2：头尾协同、潜地、四颜色弱点
→ 最终结果 → StartMenu
```

## 玩家必须能读懂的状态

| 时刻 | 反馈组合 | 失败时的可见问题 |
|---|---|---|
| 菜单 | 视频阶段、可点页面、BGM、按钮音效 | 视频／音频叠加或页面残留。 |
| 拾取 | 地面提示、手持外观、HUD 图标、颜色 | 不知道拿到什么或 HUD 与手持不一致。 |
| 攻击 | 动画、命中 FX、音效、Boss 当前槽变化、镜头冲击 | 错色仍掉血、一次攻击多结算。 |
| 受击／Dash | 生命格、击退／闪烁、无敌窗口、慢动作脉冲 | 连续扣血、死亡后仍可操作。 |
| Boss 阶段 | 当前弱点、未来七段、攻击预警、教程 | 提示陈旧、Boss1/2 HUD 同时存在。 |
| 切场景 | 唯一 Loading、进度与淡出 | 双进度条、无响应、旧声音或对象残留。 |

## 可访问性与一致性

- 关键状态至少由图标／颜色之外的一种反馈（位置、动画、声音或文字）辅助传达。
- 暂停、教程、结果等模态页面必须阻断底层输入。
- 以 1920×1080 作为当前验收基线；未来适配需求需按 GF UI 规范新增规格和测试。
