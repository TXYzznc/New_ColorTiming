# GF 业务配置表实施说明

## 目标

ColorTiming 的可调业务数据统一以 `GameData/DataTables/ColorTiming/` 中的 Excel 为权威源，经项目既有 GF 表格工具生成 `Assets/Game/DataTable/ColorTiming/` 文本和 `Assets/Game/Scripts/DataTable/ColorTiming/` 行类型。运行时只读取 GF DataTable，不再从 ScriptableObject、场景数值或代码常量读取同一份业务配置。

## 配置表职责

| 表 | 职责 |
|---|---|
| `ColorTimingBattleTable` | 场景、Boss/Player/生成规则关联、胜利流转、教程、BGM、镜头范围 |
| `ColorTimingPlayerTable` | 生命、伤害、移动、冲刺、输入容差、无敌、受击和死亡表现 |
| `ColorTimingBossTable` | 弱点构成、攻击冷却、Boss2 头/尾移动与钻地、血条与受击闪烁 |
| `ColorTimingBossAttackTable` | Boss1 分距离权重、不可连续规则、攻击语义、音效和技能 ID |
| `ColorTimingWeaponTable` | 武器身份、Animator 值、HUD/光标索引、蓄力提示、Controller 和技能 ID |
| `ColorTimingWeaponSpawnRuleTable` | 每关允许组合、生成间隔、同屏上限、保底阈值和教程伤害上限 |
| `ColorTimingSkillTable` | GF.Entity 名称到技能语义、生命周期、运动/弹道/阵列参数及 Cue 的映射 |
| `ColorTimingSoundCueTable` | 语义 Cue、动画事件键、音频资源路径、GF 声音组、循环、音量和优先级 |
| `ColorTimingPresentationTable` | Loading、场景进度、教程、HUD、Boss Pip、主菜单视频和结果渐显参数 |

## 运行时链路

`ColorTimingCompositionRoot` 在 GF DataTable 加载完成后创建 `GfColorTimingConfiguration`。仓库启动时一次性建立索引并校验唯一键、枚举、跨表引用、Boss 攻击权重、武器资源和声音 Cue；缺表、缺行、重复键或无效引用直接失败，不使用静默默认值。

配置通过显式接口注入 BattleSession、Actor、Spawner、GF.Entity、GF.Sound 和 GF.UI。动态技能按 GF.Entity 名称绑定技能行；Boss 和玩家音效只传语义 Cue ID；UI 武器索引从武器表读取。

## 仍由场景或预制体保存的内容

以下内容不是调参数据，继续保留序列化引用：Transform/出生点/相机目标、Animator/Spine/SpriteRenderer/Collider、Sprite/材质/动画/视频、技能和特效 Prefab、UI 节点及按钮引用、UnityEvent 和 AnimationEvent 合同。它们属于美术结构或场景装配，强行放进表格会降低可读性并增加 GUID/子对象引用风险。

原有 AudioClip、Sprite、AnimatorController、AnimationClip、材质、视频和 Prefab 内容没有被重制或破坏；DataTable 只记录其资源路径或业务 ID。

## 已淘汰配置源

运行时已不再使用 `WeaponSpawnRuleAsset`、`PlayerSceneProfileAsset`、`HeroWeaponAnimationCatalogAsset`、`BossSoundCueCatalogAsset`。对应资产、类型和只服务于它们的一次性迁移工具已删除，场景和 Player/MainMenu Prefab 中的旧字段引用已清理。

## 修改与验收

1. 只编辑 `GameData/DataTables/ColorTiming/*.xlsx`。
2. 在 Unity 执行 `Game Framework/GameTools/Refresh All Excels【刷新所有数据表】`。
3. 确认 Unity 编译为 0 错误。
4. 依次验收 StartMenu、Boss1、Boss2：音效、镜头、武器生成、技能运动、Boss 攻击、HUD、Loading 和胜负流转。
5. 修改跨表 ID 时必须同步修改引用表；运行时配置仓库会在启动时阻止不完整配置进入战斗。
