# 固定窗口注册与自动派发

窗口消息是派发单的传输与状态监控层；派发单、OpenSpec、提交、验收证据和项目权威计划仍是正式事实来源。

## 首次注册与派发

1. 用户创建长期职能窗口，或明确要求制作人创建指定窗口。
2. 项目为窗口设置稳定标题和项目绑定；制作人将实际 `threadId`、`hostId` 和项目标识写入本机注册表。
3. 制作人写入派发单、登记中央占用并核对无冲突后，向已注册窗口发送最小启动消息。
4. 注册无效、窗口不匹配或发送失败时，记录原因并降级为用户手动派发；不得路由到看似相近的项目窗口。

真实注册表为 `.ai/dispatch/window-registry.local.json`，必须被 Git 忽略。仅在标题、职能和项目绑定都匹配时自动重绑；任何歧义交由用户确认。

## 最小启动消息

```text
你是 <project-name> 的 <role-window>。请处理派发 <dispatch-id>。
先阅读 <dispatch-document> 并完成启动检查。正式事实以派发单、OpenSpec 与项目文档为准。
不要自行扩大范围；仅显式暂存授权路径并提交，不推送。
若需要制作人授予锁、权限、协调冲突、归档或交接，请暂停相关工作并发送可执行请求。
```

发送前制作人必须确认派发已登记、目标窗口有效且绑定正确、目录/文件/工具/索引锁无冲突，并在需要驱动工具时登记对应实例锁。

## 回传门槛

专业窗口仅在以下情况发送跨窗口请求：

- 申请或释放 Git 索引、工具、目录/文件锁或新增写权限；
- 发现不可自行消除的设计冲突、越界需求、外部阻塞或跨职能依赖；
- 完成结果需要阶段放行、测试派发、中央占用更新或正式交接；
- 达到增量归档门槛且归档由制作人独占维护或需跨职能汇总；
- 发生 S0、S1 或 S2 暂停事件。

正常讨论、普通进度、阶段内测试或无需制作人动作的完成不得广播。请求至少包括派发 ID、事件类型、需要制作人采取的动作、验证结果和当前占用资源。制作人可在协调回合等待必要回传；低频巡检仅作兜底，不能替代主动回传。

## 自动化边界

- 未经用户明确要求，不创建新的用户可见窗口。
- 自动化不代替用户的方案、验收或权限扩张决定，也不得自动改写权威计划。
- 同一工具实例同一时段只允许一个窗口驱动；派发前确认目标项目和实例身份。
