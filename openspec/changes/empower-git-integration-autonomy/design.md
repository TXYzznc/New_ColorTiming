## Context

用户要求 Git 集成窗口接收大概任务后自行查看、分析、校验和处理小型格式问题。现有合同要求完整精确路径，且禁止一切内容修复，导致主实现窗口承担本应由提交窗口完成的机械工作。

## Goals / Non-Goals

**Goals:**

- 让 Git 集成窗口从目标和边界中自行识别候选文件与提交单元。
- 允许范围内可逆、非语义的格式与生成镜像修复，并在修复后自行重跑门禁。
- 保留对业务语义、资源、测试和授权边界的严格保护。

**Non-Goals:**

- 不让 Git 集成窗口设计或修复功能、改写测试断言、处理 Unity 序列化资产或接受范围不明的代码变更。
- 不允许范围外暂存、全量暂存、推送、合并、变基或历史改写。

## Decisions

### 1. 用任务范围取代由请求方预枚举的文件清单

请求必须给出目标、允许范围、永久排除项、验收／验证要求及授权依据。Git 集成窗口负责用 Git 状态、OpenSpec 和差异盘点推导精确暂存路径。

### 2. 低风险自修复仅限无语义变更

允许修复 Markdown／文本尾随空白、EOF 空行、行尾一致性、UTF-8 BOM 兼容和由受管源生成的 agent 镜像不同步。所有修复必须在允许范围内并重新通过门禁。

### 3. 语义问题仍交回实现窗口

任何代码行为、测试断言、Prefab/场景/资源、数据内容、需求不一致、合并冲突或范围歧义都停止并报告，不由 Git 集成窗口猜测修复。

## Risks / Trade-offs

- [窗口越权修改] → 允许范围和永久排除项仍为硬门禁；自修复类别白名单化。
- [格式修复改变文档视觉] → 仅采用无语义、可审计的标准化；每次重新运行差异和门禁。
- [任务描述太宽] → Git 窗口先报告候选提交计划；范围不足时请求用户或制作人。

## Migration Plan

1. 更新角色和 GitIntegration 文档的请求合同与权限边界。
2. 更新派发模板的 Git 请求说明，生成 Codex 角色镜像。
3. 严格验证 OpenSpec、角色镜像和文档链接；将新默认规则通知现有 Git 集成窗口。
