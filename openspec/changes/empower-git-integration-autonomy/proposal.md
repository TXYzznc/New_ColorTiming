## Why

首笔 Git 集成任务因格式门禁失败而要求主窗口逐项修复和重新提交完整路径，违背了专职窗口应自行查看、分析和校验的目的。Git 集成窗口需要在安全边界内拥有任务发现、验证和非语义性修复能力。

## What Changes

- 将 Git 集成请求从“精确文件清单”调整为“目标、范围、排除项、验证与授权依据”的任务合同。
- 允许 Git 集成窗口自行盘点受影响文件、拆分独立提交、运行校验，并修复范围内无语义变化的格式、行尾、EOF、编码和生成镜像一致性问题。
- 保持业务逻辑、测试语义、资源内容、范围授权和不明确故障的升级边界。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `git-integration-workflow`: 扩展 Git 集成窗口的任务发现与低风险自修复边界。

## Impact

- 修改 Git 集成角色源、Dispatch GitIntegration 工作流与入口模板；生成对应 Codex 镜像。
- 不修改产品运行时代码、场景、资源或当前未提交重构实现。
