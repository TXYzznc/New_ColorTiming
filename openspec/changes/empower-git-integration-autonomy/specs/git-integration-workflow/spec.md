## MODIFIED Requirements

### Requirement: 专职 Git 集成角色与请求合同
项目 MUST 定义 `git-integration` 角色，作为共享工作树中常规暂存和提交的唯一执行者。请求 MUST 提供任务目标、允许范围、永久排除项、验证要求和授权依据；Git 集成窗口 MUST 自行检查工作树、相关 OpenSpec 与差异，推导精确暂存路径和独立提交单元。

#### Scenario: 范围明确的概括任务
- **WHEN** 专业窗口提供目标、允许范围、排除项、验证要求与授权依据，但未枚举文件
- **THEN** Git 集成窗口 MUST 自行盘点候选文件、复核范围并完成安全的提交计划。

### Requirement: 明确暂存和提交门禁
Git 集成窗口 MUST 读取工作区和暂存区状态、仅使用从获批范围推导出的精确路径暂存、复核暂存文件清单并执行 `git diff --cached --check`。提交标题、概要和正文 MUST 使用中文；术语、文件名、类型名、派发 ID 与 OpenSpec ID 可保留原文。窗口 MAY 在允许范围内自行修复不改变语义的尾随空白、EOF 空行、行尾、UTF-8 BOM 兼容或受管生成镜像不同步，并 MUST 在修复后重新执行门禁。

#### Scenario: 格式门禁失败
- **WHEN** 暂存范围内仅存在尾随空白、EOF 空行、行尾、UTF-8 BOM 或受管生成镜像不同步问题
- **THEN** Git 集成窗口 MUST 在允许范围内自行修复、重新暂存并重跑全部提交门禁。

### Requirement: 禁止的 Git 操作与异常升级
Git 集成窗口 MUST NOT 修改业务实现、测试语义、场景、Prefab、资源、数据内容、需求范围或优先级，亦不得推送、合并、变基、切换分支、改写历史或清理归属不明的现场。它遇到范围／归属不明、语义性验证失败、只读内容混入且不能安全分离、仓库异常或新用户授权需求时 MUST 停止并升级用户或制作人。

#### Scenario: 语义性验证失败
- **WHEN** 编译、测试、资源或功能验证失败需要改变实现或验收语义
- **THEN** Git 集成窗口 MUST 保留现场并交回对应实现窗口，而不得自行修复。
